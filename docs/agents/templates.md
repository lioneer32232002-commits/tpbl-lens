# 派工 Prompt 模板

> 用法：複製對應模板，填掉 `{...}` 空格，整段作為 Agent 工具的 prompt。全部用繁體中文。
> 每個模板都內建「三件套」：目標與動機／驗收條件／回報格式。不要刪掉驗收條件那段。

## 1. 搜尋／盤點（agentType: Explore）

```
目標：{找什麼，例如「找出所有計算 PPP 的地方」}。
動機：{為什麼要找，例如「要改公式，需要確認影響範圍」}。
範圍：{目錄或檔案類型，例如「js/ 與 *.py，排除 dist/ 與 docs/」}。搜尋廣度：{medium|very thorough}。

驗收條件：
- 每個結果附 檔案:行號 與一句話說明
- 明確說「找完了」或「以下範圍沒掃到：…」，不要默默漏

回報格式：條列，總長 {50} 行以內。不要貼大段程式碼。
```

## 2. 實作（agentType: general-purpose）

```
目標：{做什麼改動}。
動機：{為什麼，讓你在細節上能自行取捨}。
背景：{相關檔案路徑與已知約束，例如「公式規範見 docs/DATA_RULES.md，圖例規則：不用圖示符號、用彩色文字」}。

做法邊界：
- 只改 {列出允許改的檔案/目錄}，不碰 dist/（build 產物）
- 不做 git commit/push（由主對話統一處理）
- 卡住或需要做範圍外的改動時，停下來回報，不要自行擴大

驗收條件（完成前逐條自查）：
- {條件1，例如「python build.py exit 0」}
- {條件2，例如「pytest 全綠」}
- {條件3，例如「頁面上 X 區塊顯示 Y」}

回報格式：改了哪些檔案（檔案:行號）、每項驗收條件的實際證據（指令輸出摘要）、有沒有殘留問題。{80} 行以內。
```

## 3. 重構（agentType: general-purpose；建議先跑 Plan）

```
目標：{重構什麼，例如「把 championship.js 的系列賽狀態判斷抽成獨立函式」}。
動機：{例如「歷史賽季功能要複用這段邏輯」}。
鐵律：重構＝行為不變。任何對外可見的行為差異都算失敗。

做法邊界：
- 改動範圍：{檔案清單}
- 分小步進行，每步之後跑 {python build.py / pytest} 確認不壞

驗收條件：
- {驗證行為不變的方法，例如「build 前後 dist/championship/index.html 的 diff 只有 hash 版號」}
- 既有測試全綠、沒有刪掉或跳過任何測試

回報格式：每一步做了什麼＋驗證輸出；若中途發現「行為不變」保不住，停下並回報原因。
```

## 4. 研究（agentType: general-purpose，需查網路時）

```
題目：{要回答的問題，例如「TPBL 官方 API 是否提供上季 division_id」}。
動機：{答案會決定什麼}。
方法要求：
- 每個結論附來源（URL 或 檔案:行號），區分「查證過的事實」與「推測」
- 查不到就寫「查不到」，不要編造
- 兩個來源矛盾時，兩個都列出來

驗收條件：直接回答題目本身（是/否/數字），再附依據。
回報格式：先一段結論，再條列依據。長報告落檔到 {路徑}，回報只給路徑＋摘要。
```

## 5. 審查（agentType: general-purpose；fresh context，不給過程）

```
你是審查者，沒有看過實作過程——這是刻意的，請以懷疑的眼光驗收。
待審改動：{檔案清單或 git diff 範圍}。
原始需求：{使用者要什麼，逐字或忠實轉述}。

審查重點（按序）：
1. 需求有沒有做到（對照原始需求逐項檢查，不是對照實作者的說法）
2. 有沒有寫錯：邏輯、公式（權威版本在 docs/DATA_RULES.md）、路徑、編碼（本專案檔案含中文，注意 encoding='utf-8'）
3. 有沒有破壞既有行為：{指出要檢查的相鄰功能}

驗收動作（實際執行，不是用看的）：
- {python build.py / pytest / python -c json.load 檢查}

回報格式：問題按嚴重度排序，每條附 檔案:行號＋一句話＋建議修法；沒問題就明說「通過，證據：…」。不要客套。
```

## 通用注意事項

- 模板裡的花括號數字（如 `{50}` 行）是預設上限，可依任務調整，但**必須給上限**。
- 派工後 subagent 回報若不符回報格式，先要求它重新整理，不要自己去讀它的過程。
- 升降級與重試上限規則見 `dispatch.md` 第五節。
